多Agent竞品分析系统

这个项目面向竞品调研场景，核心目标不是简单生成一段分析文本，而是让系统像一个小型调研团队一样完成任务拆分、证据采集、分析对比、审校和正式报告输出。

Python LLM Agent Controller -> Manager -> Executor Markdown JSON

项目背景

竞品分析常见的问题是信息来源分散、结论缺少证据、过程不可解释。这个项目把“候选竞品、公开信息、证据、分析结论、审校结果、最终报告”拆成结构化链路，让 AI 生成内容时有更清晰的上下文和边界。

核心架构
  • Controller 负责总控、任务拆解和流程推进。
  • Manager 负责候选筛选、证据整理、报告生成和审校协调。
  • Executor 负责具体采集、单竞品分析、引用检查和结论校验。
核心数据结构
  • ProjectContext：保存任务主题、输出目录和运行配置。
  • EvidenceItem：保存来源、摘要、证据类型和可信度。
  • AnalysisFinding：保存分析结论、支撑证据和风险信息。
  • ReportOutput：统一承载 Markdown 与 JSON 输出。

真正有价值的地方

  • 项目链路完整，能从行业主题输入跑到正式报告输出，不停留在 Demo 调用层面。
  • 多 Agent 分工边界清晰，便于解释每个角色为什么存在、负责什么、不负责什么。
  • 输出不只给人看，也给系统继续处理：Markdown 便于阅读，JSON 便于扩展。
  • 审校信息参与最终建议，体现对 AI 结果可信度和可控性的关注。

面试讲法

我会重点强调这个项目不是“让大模型直接写报告”，而是把竞品分析流程拆成可解释的多 Agent 工作流，并通过结构化证据和审校字段约束最终输出。

亚马逊运营日志智能决策系统

这个项目面向跨境电商运营场景，目标是把店铺、Listing、订单、FBA 库存、广告报表和运营日志整合起来，让运营动作能被复盘、诊断和转化为任务建议。

Python FastAPI Pandas NumPy scikit-learn ECharts

项目背景

运营团队经常需要判断“某个动作有没有效果”“广告为什么花钱没转化”“库存是否存在断货风险”。如果只看单张报表，很难形成执行建议。这个系统把多源数据和运营日志放在一起分析，减少人工复盘成本。

分析维度
  • 销量、CTR、CVR、ACOS 等关键运营指标。
  • 库存风险、广告消耗、订单变化和运营动作时间线。
  • 断货风险、高 ACOS 低转化、高花费无订单等异常规则。
系统输出
  • 单品复盘和动作归因。
  • P0/P1/P2 优先级任务。
  • 库存预警、广告优化建议和执行计划。
  • FastAPI 接口和 ECharts 驾驶舱。

真正有价值的地方

  • 从“展示数据”升级到“发现问题并给出建议”，业务价值更明显。
  • 技术链路覆盖数据清洗、指标分析、规则诊断、后端接口和可视化交付。
  • 业务指标明确，面试时能讲清楚 CTR、CVR、ACOS 分别影响什么判断。
  • 能体现 Python 后端和数据分析结合解决实际问题的能力。

面试讲法

我会重点说这个项目的价值不是做一个运营看板，而是把日志、指标和规则结合起来，自动识别运营风险并生成优先级任务。

SkillFinder AI Agent 技能发现与安装工具

这个项目是一个面向 AI 编程工具生态的桌面工具，用来搜索、筛选、安装和管理 Claude Code Skills、Hooks、Plugins 以及 Codex Skills。

Python Tkinter GitHub Search API ThreadPoolExecutor Git

项目背景

使用 AI Agent 工具时，经常需要去 GitHub 搜索技能仓库、阅读 README、克隆项目、复制配置、检查本地目录。这个过程分散且重复，SkillFinder 的目的就是把这套流程产品化。

核心功能
  • 按关键词、Topic、Star、更新时间筛选技能仓库。
  • Claude Code 与 Codex 技能生态分类展示。
  • 一键安装、批量勾选、安装撤回和本地目录管理。
  • 更新检测、中文描述翻译和异常提示。
工程处理
  • 接入 GitHub Search API 获取仓库信息。
  • 使用 ThreadPoolExecutor 并发查询提升搜索速度。
  • 处理 GitHub 限流、网络异常、空结果和本地安装状态。
  • 封装为桌面 GUI，降低工具使用门槛。

真正有价值的地方

  • 项目从自己的真实效率痛点出发，不是为了堆功能而做功能。
  • 覆盖 API 接入、并发任务、本地文件管理和 GUI 交互多个工程点。
  • 体现对 AI 编程工具链生态的实际理解。
  • 能说明自己不仅会使用工具，也会把工具流程自动化和产品化。

面试讲法

我会重点讲这个项目如何把“找仓库、读说明、克隆配置、检查更新”的重复流程整合到一个桌面工具里，体现工具化思维和工程落地能力。
